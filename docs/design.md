# Private-first scope

M1 is a disposable, Linux-first lab. An owner on the desktop terminal approves one device certificate fingerprint for one known task, then starts a fixed local demo task. The distinct TLS client follows numbered events, resumes from its durable cursor after loss, and loses access on revocation. The task never runs shell, provider, or user-supplied code. No network outside loopback is supported by this build.

## Boundaries

- The daemon runs under an unprivileged Unix account. A Unix socket in its private state directory is the owner-only authority. Anyone running as that UID (and privileged host administrators) can act as the owner. The TLS listener has no admin routing or write capability. There is no relay or discovery.
- The lab provisions a disposable CA and independent host/client keys. The viewer checks the server name and pinned server certificate in addition to CA validation. The host requires TLS 1.3 client certificate verification, then checks the owner's explicit grant. Trust in the CA alone gives no authorization. Enrollment is an out-of-band comparison of full SHA-256 certificate fingerprints. The service never handles client private keys or the CA signing key. Local fixture PKI is not a rollout or key-distribution design.
- An approved TLS device can mint an opaque `events:read` session valid for at most 60 seconds. The daemon retains only a hash of the latest token per device and binds authorization to the authenticated certificate on every request. Task grants, expiry and revocation are checked on every event page, including previously established transport connections. Revocation cannot erase data already delivered or retract responses authorized before it committed.
- Host task IDs are idempotency keys. Each state transition and event write is one SQLite transaction. On restart the worker advances persisted state, never replays an external side effect. The client commits a validated contiguous batch and its cursor in one SQLite transaction before presenting it. A transport retry only reads or refreshes a session. Replay storage is deliberately bounded and does not silently truncate.
- All request and fixture data is synthetic. No credentials, payloads, authorization headers, or task events enter daemon logs. No telemetry, host discovery, filesystem browsing, reverse shell, or arbitrary process launch. The implementation is not a production ingress or a sandbox for external commands.

## Milestones and rollback

1. M1 proves local opt-in approval, one task, recoverable transport loss, bounded replay, and revocation with negative tests. A release/build tag is not required for this lab. Roll back this lab by stopping the process and using the previous commit with a fresh disposable fixture.
2. M2 validates a T1OS companion profile in a disposable VM. Keep daemon state and credentials independent of T3 and keep existing T3 policy and its two-port allowlist untouched. Model a separate opt-in exposure rule and a narrow local broker if operator and daemon run under different users. Test against the pinned v0.1.10 runtime before adding any T3 event adapter. Do not assume v0.1.12-only APIs exist.
3. M3 compares a direct private route with a self-hosted discovery service. Keep static pairing and turns usable without discovery. A candidate must not terminate end-to-end host/device TLS. Extend negative tests and measure real mobile and roaming networks before promotion.
4. M4 adds a client UX over the approved protocol, separate from compatibility experiments with upstream client builds. Verify keyboard use, focus, status announcements, contrast and narrow viewports before calling it usable. The M1 CLI has explicit text states and no color dependency, not a graphical accessibility assessment.
